# Muse-multiple 交互原型

用于确认首页、仪表盘、独立控制台、账号标签页和设置的布局与交互。它是独立的静态 HTML/CSS/JavaScript 原型，不是 Rust/Tauri 正式应用，不修改三个参考项目，也没有安装依赖。

## 打开

直接在浏览器打开本目录的 `index.html`，或使用 PI-Desktop 的 HTML 预览。首次包含三个虚构的演示档案。

## 体验路径

1. 首页点击「添加 Muse 账号」，输入名称后打开模拟登录页；空白名称不能提交，取消不创建档案。
2. 点击「演示网页认证」，在所属账号旁新增认证标签。可切换原标签或切换其他账号，再返回继续。
3. 点击「模拟认证完成」回到对话示意页。消息仅在本地内存展示，不发送到 Muse。
4. 标签栏「＋」可反复新建标签，地址栏输入 http/https 网址并回车，模拟在当前标签导航。所有标签（包括初始 Muse 标签）都可关闭；关完后显示空白入口，不移除账号、不强制重新打开主标签。存在未发送文字时先确认。
5. 左侧账号「⋯」或右键菜单支持改名、备注、刷新、休眠和移除；当前账号休眠及移除有确认。
6. 设置提供主题、界面缩放、网页缩放、关闭偏好和自动休眠（默认 15 分钟）。修改后尝试自动保存。
7. 顶部「仪表盘」仅打开概览页，展示账号数、页面驻留、休眠、标签数和账号状态表。旁边的「控制台」独立展开/收起右侧底部日志面板，可调整高度、筛选、清屏和复制脱敏诊断信息；不会切换当前页面，开关状态不随页面导航改变。默认收起。所有数据仅来自原型状态。
8. 窄窗口或收起侧栏后，用左侧对话图标打开账号列表。桌面布局建议在 1100px 以上宽度查看。

快捷键（在账号页）：`Ctrl+T` 新建标签，`Ctrl+Tab` / `Ctrl+Shift+Tab` 切换标签，`Ctrl+W` 关闭当前标签，`Ctrl+R` 模拟刷新。浏览器或宿主可能优先拦截这些快捷键；正式桌面版需重新验证。

## 数据与演示边界

- 页面没有 iframe、真实 WebView、网络请求、Muse/Meta 登录或账号凭据。不要输入真实密码、验证码或其他敏感信息。
- 浏览器 `localStorage` 中的 `muse-multiple.prototype.v1` 只保存演示账号 ID、名称、备注、配色、最近使用时间和设置。不保存消息、草稿、标签网址和认证状态。
- 重新打开始终进入首页，不恢复认证标签；自建演示账号可能重新显示待登录，这是刻意不持久化模拟认证状态的结果，不代表正式会话行为。
- 自动休眠只是清空演示页面状态；认证标签与非空草稿会阻止自动休眠。它不验证真实资源释放、会话持久化、生成回复或上传检测。
- 「最小化到系统托盘」仅保存选项，不控制系统窗口。GitHub 链接已指向 `https://github.com/jiajiayaofacai/Muse-multiple`，原型使用浏览器新标签打开；正式桌面版必须通过受限原生接口交给系统浏览器。使用文档地址尚未配置。
- 原型不是真实网站的截图或完整复刻。Tauri 新窗口关联、认证回调、账号隔离、重启保持登录均待后续原生验证。

## 检查

在工作区根目录执行：

```powershell
node --check .\prototype\app.js
node .\prototype\state.test.cjs
```

状态测试使用内存中的 DOM 替身和合成数据，不接触浏览器本地记录或用户资料。覆盖仪表盘状态、自由新建/关闭标签、关闭最后标签后的空态、导航地址校验、认证来源关闭后的返回、多标签草稿隔离、休眠保护及持久化范围；不能替代浏览器排版及原生登录测试。
